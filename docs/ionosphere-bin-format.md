# `ionosNN.bin` Reference Ionosphere File Format

The ITURHFProp prediction engine's "Reference Ionosphere" is the file set
`ionos01.bin` … `ionos12.bin` (one file per month) containing monthly median
maps of the two ionospheric parameters used by the ITU-R P.533 model:

- **foF2** — F2-layer critical frequency (MHz)
- **M(3000)F2** — the M(3000)F2 propagation factor (dimensionless)

The maps were generated by Peter Suessman's `iongrid` program from the CCIR
spherical-harmonic coefficients (1958 Geophysical Year, per ITU-R P.1239).
The engine loads the file for the requested month from the directory named by
`DataFilePath` in the `.in` input file — the filename pattern `ionos%02d.bin`
is hardcoded in `itu_r_hf/P533/Src/P533/ReadIonParameters.c`
(`ReadIonParametersBin()`), which is the authoritative reference for this
format.

A modification tool (see "Writing a modification tool" below) can create a
custom ionosphere by rewriting the float payloads of these files in a copy of
the data directory, then pointing the app at that copy via `ITURHF_DATA_PATH`
(see `.env.example`).

## Binary layout

Each file is exactly **11,197,844 bytes**:

| Offset | Size (bytes) | Content |
|---|---|---|
| 0 | 5 | Fortran record overhead (opaque — preserve verbatim) |
| 5 | 5,598,912 | foF2 payload: 1,399,728 × float32, little-endian |
| 5,598,917 | 10 | foF2 record tail + M(3000)F2 record header (opaque) |
| 5,598,927 | 5,598,912 | M(3000)F2 payload: 1,399,728 × float32, little-endian |
| 11,197,839 | 5 | trailing record tail (present in file, never read) |

## Payload indexing

Each payload holds a 4-D grid flattened with **hour fastest**:

```
idx = ssn * (241 * 121 * 24) + lon * (121 * 24) + lat * 24 + hour
```

| Dimension | Range | Meaning |
|---|---|---|
| `ssn` | 0–1 | 0 = SSN 0 map, 1 = SSN 100 map (engine linearly interpolates/extrapolates by the actual smoothed sunspot number) |
| `lon` | 0–240 | longitude in 1.5° steps starting at 180° W (`lon_deg = -180 + 1.5 * lon`) |
| `lat` | 0–120 | latitude in 1.5° steps starting at 90° S (`lat_deg = -90 + 1.5 * lat`) |
| `hour` | 0–23 | UTC hour |

## Writing a modification tool

- Rewrite the float payloads **in place** and preserve the 5/10/5 overhead
  bytes verbatim — the engine skips them without validation, but the payload
  offsets must not shift.
- foF2 values are in MHz (typical range roughly 1–15 MHz); M(3000)F2 is
  dimensionless (typical range roughly 2–4).
- Work on the seeded copy in `ionosphere/custom/` (created by
  `python scripts/seed_custom_ionosphere.py`), never on the bundled reference
  in `itu_r_hf/ITURHFProp/Data/`. Restore pristine data any time with
  `python scripts/seed_custom_ionosphere.py --force`.
- The engine re-reads the file on every prediction run (each run is a new
  subprocess), so map edits take effect on the next prediction without an app
  restart. Changing `ITURHF_DATA_PATH` itself *does* require a restart.

Minimal example — scale all July foF2 values by 1.2:

```python
import array

PATH = 'ionosphere/custom/ionos07.bin'
N = 2 * 241 * 121 * 24  # values per payload

data = open(PATH, 'rb').read()
foF2 = array.array('f')
foF2.frombytes(data[5:5 + 4 * N])
foF2 = array.array('f', (v * 1.2 for v in foF2))
with open(PATH, 'wb') as f:
    f.write(data[:5] + foF2.tobytes() + data[5 + 4 * N:])
```
